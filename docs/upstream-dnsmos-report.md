# Emilia 系列上游 DNSMOS 分布报告

统计日期 2026-10-12（PDT）。对象是统一根下 `emilia`、`emilia_yodas`、`emilia2` 三个基础数据集（v0.1）中上游自带的 DNSMOS 分数，
全量读取，共 184,069,533 行，没有缺失值。分数不是本仓库计算的，本仓库只读取、不改动。
本文回答四个问题：三者是否同一个模型、分数怎么分布、分数是否受语言影响、对后续导入 annotation 和筛选数据意味着什么。

## 1. 结论

1. **同一个模型、同一个尺度。** 三者都是 DNSMOS P.835（`sig_bak_ovr.onnx`，非 personalized）经多项式校准后的 OVRL，
   上限都在 3.76–3.78，可以直接比较。
2. **下限是上游过滤阈值的硬截断：**
   - Emilia：全部语言 3.0；
   - Emilia-YODAS：全部语言 2.4；
   - Emilia2：英文、中文 3.0，其余 39 种语言（含粤语）2.4。
3. **时长影响很大，越短分数越低。** Emilia2 小于 2 秒的片段均值 2.90，15–30 秒为 3.22；Emilia 和 YODAS 也是同样的单调趋势。
4. **看不出明显的语言偏差。** Emilia2 非英非中语种整体均值低约 0.3，主要是两套阈值造成的。只比较 3.0 以上的部分时，
   主要语种均值在 3.17–3.23，与英文、中文的 3.21 基本持平。
   不过 DNSMOS 论文说明其训练数据以英语为主，官方没有分语言的验证，所以跨语言用同一个绝对阈值没有官方依据。
5. **selection-v2 没有按 DNSMOS 筛选**（[selection](selection.md)），这次发布的 features 包含 YODAS 和 Emilia2 中 2.4–3.0 的部分。

## 2. 数据来源与字段

| 数据集 | 上游 | 分数位置（`metadata_json`） | 粒度 |
| --- | --- | --- | --- |
| emilia | Emilia（Emilia-Pipe） | `upstream.dnsmos` | 每条 utterance |
| emilia_yodas | Emilia-YODAS（沿用 Emilia-Pipe） | `upstream.dnsmos` | 每条 utterance |
| emilia2 | Emilia2（Emilia2-pipe） | `upstream.short.dnsmos` | 每个 short 片段 |

模型信息：
- Emilia2-pipe 的示例配置（`examples/qwen3_asr.json`）使用 DNSMOS P.835，模型文件 `sig_bak_ovr.onnx`，ONNX Runtime 推理，非 personalized。
  它输出 SIG（语音信号质量）、BAK（背景质量）、OVRL（整体质量）三项，pipeline 只保存并用校准后的 OVRL 过滤。
- Emilia 与 Emilia-YODAS 的模型与阈值：DNSMOS P.835 `sig_bak_ovr.onnx` 的 OVRL，发布阈值分别为 3.0 和 2.4。

以上两条由数据负责人提供，下面的数据分布与之吻合。上游 README（`DATA-TTS/Emilia2/Emilia2_TTS_m4a/README.md`）只说明每条带 `dnsmos` 字段，
没有写模型。三个数据集都只有 OVRL 一个分数，没有 SIG、BAK，也没有窗口级明细。

Emilia2 每行是一个 short 片段，分数随片段而定，long 和 dialogue 层没有分数进入本仓库。按接入方式分：
- `short_crop`：从长录音裁出，82,830,202 行；
- `standalone_transcode`：本来就是独立短音频，直接转码，17,010,195 行。

## 3. 方法

用 `scripts/report_upstream_dnsmos.py` 全量读取三个 `samples.lance` 的 `language`、`duration_seconds`、`metadata_json`，
按（数据集、语言、时长分段、Emilia2 接入方式）汇总 0.01 宽的直方图和时长。分位数按 0.01 的分箱取值，均值按分箱中心计算，误差不超过 0.005。
原始汇总在 `artifacts/analysis/upstream-dnsmos-20261012.json`（不入库）。

## 5. 阈值：硬截断与按语言阈值

各语言的最小分数：
- Emilia：6 种语言全部为 3.00。
- YODAS：全部为 2.40。
- Emilia2：英文、中文为 3.00，其余 39 种语言为 2.40。

在每个下限处，紧贴阈值的 0.01 分箱的行数都约为下一个分箱的一半，例如 Emilia 英文 115,303 对 227,700，Emilia2 德语 73,711 对 146,018。
这是"四舍五入到 0.01 的分箱只包含阈值以上的一半"的结果，说明阈值处是硬截断，阈值以下没有残留。

**因此 Emilia2 的整体分布是两种阈值混合的结果。** 英文和中文按 3.0 过滤，其他语言按 2.4 过滤，
后者中行数最多的 13 个语种里，除粤语（23%）外都有 52%–66% 的行落在 2.4–3.0；
不少小语种更高（如 nl 81%、sv 78%、cs 74%）。

## 6. 时长效应

| 时长 | emilia 行数 / 均值 | emilia_yodas 行数 / 均值 / <3.0 | emilia2 行数 / 均值 / <3.0 |
| --- | --- | --- | --- |
| < 2 s | — | — | 27,176,276 / 2.897 / 55.1% |
| 2–3 s | 7 / 3.134 | 203 / 2.930 / 52.7% | 19,108,351 / 3.020 / 35.7% |
| 3–5 s | 9,709,730 / 3.239 | 9,337,453 / 3.060 / 33.1% | 24,397,208 / 3.074 / 28.5% |
| 5–9 s | 14,707,721 / 3.281 | 15,858,245 / 3.148 / 22.5% | 16,412,708 / 3.117 / 23.9% |
| 9–15 s | 10,230,857 / 3.296 | 12,286,353 / 3.183 / 17.9% | 4,947,189 / 3.158 / 19.1% |
| 15–30 s | 5,604,543 / 3.289 | 6,421,759 / 3.184 / 16.9% | 7,786,931 / 3.215 / 10.9% |
| ≥ 30 s | 11,373 / 3.204 | 60,892 / 3.168 / 12.7% | 11,734 / 3.222 / 10.1% |

三者都是越短分数越低，到 9 秒左右才稳定；9 秒正是 DNSMOS 的输入长度。官方推理对短于 9 秒的音频会循环拼接到 9 秒，
短片段的分数因此带有系统性偏低，不完全反映听感。Emilia 和 YODAS 基本没有 3 秒以下的片段，
而 Emilia2 有 46% 的行（4,628 万行，约 2.3 万小时）短于 3 秒，这是 Emilia2 整体分数偏低的第二个原因。

解读：
- 语言之间的整体差异方向不一致：Emilia 中各语言几乎相同；YODAS 中英文反而最低（低分段 27%，其他语言 1%–5%）；
  Emilia2 中非英非中语种最低。如果 DNSMOS 对非英语有系统性低估，三者应该一致偏向英文。
- 同样只看 3.0 以上的部分（阈值以上，口径相同），Emilia2 主要语种为 3.17–3.23，英文、中文为 3.21，差距在 ±0.05 内；
  个别小语种略低（nl 3.14、sv 3.16）。
  Emilia2 非英非中语种均值低约 0.3，主要来自它们按 2.4 而不是 3.0 过滤。
- 剩下的差异（2.4–3.0 段占比高低）反映的是各语种来源的录音条件，从分数本身无法区分是录音质量还是模型偏差。

## 9. 文献：DNSMOS 对不同语言是否一致

- DNSMOS（P.808 版）论文说明，训练数据以英语为主，不含非英语语种和唱歌。在 DNS Challenge 2 盲测结果上，
  基础模型与人工打分的 SRCC（按降噪系统汇总、分类别）为：英语 0.78、非英语 0.67、声调语言 0.51。
  经过多阶段自教学后，最好的配置提升到英语 0.93、非英语 0.92、声调语言 0.87。
- DNSMOS P.835 论文用 DNS Challenge 3 的 P.835 人工评分训练，没有列出训练数据的语言构成，也没有给分语言的结果。
  测试集包含英语、非英语、声调语言等类别。单条音频层面与人工打分的相关（OVRL）为 PCC 0.82，按降噪模型汇总后为 0.98。
- 设计目标是给降噪系统排名，汇总后才可靠；单条打分有较大噪声。没有找到按语言对比人工打分的公开研究。

## 10. 对后续工作的影响

1. **导入 annotation：** 契约 [05](data-contract/specs/05-annotations.md) 已规定 Emilia/YODAS 的 `upstream.dnsmos`
   映射为 upstream_dnsmos 列。Emilia2 的分数在 `upstream.short.dnsmos`，导入时需要单独映射，并且应当记录：
   - 模型（P.835 `sig_bak_ovr.onnx`，OVRL，校准后，非 personalized）；
   - 粒度（utterance / short 片段）；
   - 每个数据集、每种语言的上游过滤阈值。

   这样下游可以知道截断位置。
2. **作为 stage 2 pretrain 的筛选依据：**
   - 三者尺度一致，可以用同一个 OVRL 阈值。但阈值低于 3.0 时，只对 YODAS 和 Emilia2 的非英非中语种起作用，
     因为 Emilia 与 Emilia2 的英文、中文已经在 3.0 处被截断。
   - 短片段系统性偏低。如果统一卡 3.0，Emilia2 小于 2 秒的片段会去掉 55%，15–30 秒的只去掉 11%，
     筛选会同时改变时长分布。可以考虑按时长分段设阈值，或者配合最短时长。
   - 跨语言没有官方校准依据。如果希望保持语种比例，可以按语言分位数设阈值，代替统一绝对值。
   - 具体阈值需要结合 selection-v2 的实际行数和小时数来定（另行统计）。

## 11. 复现

```bash
python scripts/report_upstream_dnsmos.py --out artifacts/analysis/upstream-dnsmos-<date>.json
```

在 dev host 上用 24 个进程约 7 分钟（184M 行）。输出为每个（数据集、语言、时长分段、接入方式）一行，带 0.01 宽的直方图与小时数。
