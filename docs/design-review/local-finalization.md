# 本地身份审计验证

2026-09-28，全量收尾的 SQLite 原本位于共享 quarkfs 上。
09:28 对 LibriTTS-R、VCTK、鸣潮的协调进程采样，三者仅约 15–17 KB/s 读写、
每秒约 4 次读取；LibriTTS-R 进入 finalizing 后近一小时仍未完成。

改为在本地 TMPDIR 创建独立临时 SQLite，保持原唯一约束、来源重复统计和发布检查。
连接使用 64 MiB 页缓存；不把全部样本装进内存，也不改变基础分片和记录身份。
每批输出身份扫描进度，并记录扫描、查询、提交索引各阶段耗时。

## 正确性与部署边界

77 项测试通过。新增集成测试覆盖本地目录选择、成功和唯一约束失败后的资源清理，
以及音频分片不改写；原断点恢复、来源重复统计和 checkpoint 兼容测试继续通过。
Ruff 检查与格式检查通过，contract/schema/release 保持 v0.1。

实现保存在独立 perf/local-finalization 分支，避免修改其他在跑任务固定的源代码。
用户已授权只切换 LibriTTS-R、VCTK、鸣潮三个完成全部批次验证的收尾协调者。
交接前确认没有转换 worker，退出旧协调者并取得发布锁，备份计划、保留旧代码哈希，
显式登记兼容版本后 resume；全部既有分片再次核对 SHA256，不重新生成音频。
其他任务保持原运行版本。不能覆盖正在使用的 SQLite 或热改进程计算哈希的源文件。

已发布数据的状态由正式 manifest 读取；进度脚本不再要求完成任务保留 .state。
清理前核对 complete、固定 snapshot 行数、分片清单、checkpoint 哈希与索引查询，
并确认协调进程退出、持有独占锁。运行中、失败或未发布的 release 不清理 .state。
