# FP32 小规模对照

全量启动已按用户要求暂停，新的全量任务尚未启动。本测试不改变生产默认 BF16。
目的是确认：移除按长度对齐官方 CUDA 算子的策略后，提高计算精度能否减小同精度参考差异。

## 方法

- 固定 32 条真实音频，覆盖 16 个来源，共 476.231 秒，最长 30 秒。
- 相同前端波形、权重 revision；分别显式加载 FP32 和 BF16。
- 官方参考：未修改的 `Qwen3TTSTokenizer.encode(wave, sr=24000)`，逐条真实长度推理。
- 批量候选：每批 8 条真实长度，所有层固定使用一种计算策略，不按输入长度切换。
- 双方关闭 matmul TF32 和 cuDNN TF32；不是把 TF32 测量当作 FP32。
- 数值比较分别是 FP32 对官方 FP32、BF16 对官方 BF16；不是混用参考。
- GPU 1（A800），一次预热后重复计时三次，取中位数；三次输出彼此一致。
- 计时只有推理和结果取回，包含全部 32 条；不含数据读取、解码、Lance 写入、冷启动/JIT。
  这不是满载端到端吞吐测试，也不代表 8 卡生产性能。

## 结果

下面是未使用量化边界复核的固定计算路径，用于直接观察精度影响：

| 精度 | 不同样本 | 不同 token / 总数 | token 差异率 | 批量推理中位耗时 | 峰值分配显存 |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP32 | 1 / 32 | 9 / 95,456 | 0.00943% | 0.640 s | 2.882 GiB |
| BF16 | 32 / 32 | 10,012 / 95,456 | 10.48860% | 0.154 s | 1.485 GiB |

该小测 FP32 推理耗时约 4.17 倍、峰值显存约 1.94 倍。显存是 PyTorch 峰值 allocated，
包含模型和缓存，不是整张 GPU 的占用。不同阶段有共享设备/时钟波动，不能当成稳定的生产倍率。

保留现有量化边界复核的变体，FP32/BF16 的不同 token 数仍分别为 9 和 10,012；
对应中位耗时为 0.497 s 和 0.158 s，峰值显存 2.883 GiB 和 1.519 GiB。
不能因这一短测试的计时波动宣称加入复核反而会加速。
官方逐条参考自身的三次中位耗时为 FP32 0.999 s、BF16 0.861 s，仅供参考生成成本记录。

## 解释和边界

结果支持“算法公式一致，低精度下底层分块/累加顺序的舍入差异会放大为离散 token 差异”这一归因。
FP32 将同精度官方参考差异显著降低，但仍非严格逐 token 等价，也没有测主观重建音质。
差异率不应解释为音质下降比例。

官方 FP32 与官方 BF16 在本批样本上本身有 52,071 / 95,456（54.55%）个 token 不同。
因此 FP32 对 FP32 更一致，不代表它更接近此前指定的官方 BF16 输出，也不能单凭码值差异
判断两种精度谁的听感更好。若考虑生产改用 FP32，仍需另外验证实际满载成本及重建质量；
本次只记录小规模结果，不启动全量，也不切换默认精度。

证据与复现脚本：`artifacts/codec-fp32-review/`，包含 `check.py`、`run.py`、两种精度的
JSON、官方/批量 codes NPZ 与日志。运行环境沿用 BF16 报告所记录的本地 A800 软件栈。
