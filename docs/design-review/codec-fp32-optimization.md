# FP32 优化与生产验收

目标是在保留既有 BF16 路径的前提下新增 FP32，正式运行使用 FP32；满载耗时尽量
控制在 BF16 的 1.5 倍左右，并保持与官方 FP32 很小的 token 差异。

## 数值路径

模型由官方 `from_pretrained(dtype=torch.float32)` 加载；权重、激活、累加和 RVQ
residual 使用 FP32，不先加载 BF16 再升精度。Triton dot 使用 **TF32x3** 三项补偿
Tensor Core 乘法，原生 matmul 和 cuDNN 普通 TF32 关闭。TF32x3 是 FP32 乘法的
高精度近似，不能声称严格 IEEE FP32 逐位等价。Triton 3.4 支持此模式；说明见
[Triton dot](https://triton-lang.org/main/python-api/generated/triton.language.dot.html)。

卷积缓存连续的 `[归约维度, 输出通道]` 权重，保持原有归约顺序，减少重复的非连续
访存。BF16 保留此前的 kernel 参数、权重布局、类型转换及量化行为。
两条路径共用 `packed/` 的四个数值模块，只有 dtype 所需分支，无长度 policy、
逐形状表、实验候选继承链或外部 padding。profile 将精度、乘法模式、源码、依赖、
模型权重写入特征身份，BF16 与 FP32 不能混写或恢复时切换。

## 筛选实验

同一批 32 条真实音频、16 个数据集、476.23 音频秒，batch=8，预热后 7 次中位数。
仅包含推理及结果回传；不把这组时间当作正式吞吐。

| 实现 | 秒 | 相对 BF16 | 官方同 dtype token 差异 / 95,456 |
| --- | ---: | ---: | ---: |
| 原有 BF16 | 0.14174 | 1.00× | 10,012 |
| 严格 FP32 dot | 0.64483 | 4.55× | 9 |
| FP32 + TF32x3 | 0.29265 | 2.06× | 5 |
| FP32 + TF32x3 + 权重预重排 | 0.25069 | 1.77× | 5 |

BF16 / 严格 FP32 / TF32x3 在 GPU 1 测试；预重排在同型号 GPU 3 测试，因此小测
倍数仅作筛选参考。最终性能以同 GPU 的实际 worker 回放为准。
增大卷积 tile、扩大 K 分块、卷积展开占用更多显存、替换原生 FP32 GEMM均未获得
足够稳定收益，不进入生产源码。

## 扩大精度对照

官方参考为未修改 `Qwen3TTSTokenizer.encode(wave, sr=24000)`，一次一条，
显式 FP32，普通 TF32 关闭。与候选使用完全相同的 canonical 波形。
509 条覆盖 16 数据集及边界长度（含 120 秒），共 1,140,240 个 token。
预重排候选与官方差异 **193（0.01693%）**，38 条有至少一个差异；改变输入顺序、
将 batch 从 8 改为 13 后，输出差异为 **0**。正式 Encoder 与候选逐 token 相同。

这些是离散 token 一致率，不是感知音质评价；没有据此声称听感改善。
同精度剩余差异来自浮点计算路径，包括归约顺序、注意力实现与补偿乘法近似，
临近量化边界时会改变 token 并传播到后续 residual 层。边界复核不能证明全链路等价。
官方 FP32 和官方 BF16 本身也不逐 token 等价，不能拿 BF16 reference 验收 FP32。

## 真实负载与可追溯证据

最终验证使用正式 `run_task`，固定 selection 的 AISHELL-3、CSEMOTIONS、Emilia
两个任务 lane，共 18,060 条、133,060.91 音频秒；包含读取、4 线程解码、实际长度
分组、推理、Lance 写出及结果核对。单卡双 worker，同样任务运行两轮。官方 FP32
逐条参考在独立 GPU 上生成，比较按 target_id 与波形 hash 对齐，而非文件行顺序。

结果和脚本保存在 `artifacts/codec-fp32-optimization/`，生产运行冻结验收证据副本。
同一张 A800（GPU 4），取两 worker 完成全部两轮的最大 wall time：

| 路径 | 两轮完整耗时 | 样本/秒 | 单 worker 峰值 allocated 显存 |
| --- | ---: | ---: | ---: |
| 保留 BF16 | 125.534 s | 287.73 | 4.005 GiB |
| 新 FP32 | 167.193 s | 216.04 | 7.943 GiB |

FP32 / BF16 完整耗时为 **1.332×**，满足约 1.5× 的目标。两 worker 累计 encode
计时分别为 190.029 / 124.229 s（1.530×），包含调用中的 CPU/GPU 等待，不能当成
单 GPU 独占 kernel 时间。这里使用完整流水线吞吐作判断，不以单条延迟代替。
共享机器上存在其他任务，绝对吞吐会随 I/O 与 GPU 竞争波动；不能将短测外推为
128M 条全量完成时间保证。脚本保存逐 task/batch 时间和 GPU 利用率。


18,060 条与官方 FP32 的最终对照：**4,235 / 26,749,056 token 不同（0.01583%）**，
736 条至少有一个 token 不同；两轮落盘输出的 token 差异为 **0**。每个 target 的
canonical 波形 hash 和输出形状均一致。509 条在八张 A800 上的正式 Encoder 输出
均逐 token 等同优化候选，同一 profile，每卡官方差异均为 193。
BF16 509 条回归与整理前实现逐 token 完全一致。

| 数据集 | 样本 | 不同 token | 总 token |
| --- | ---: | ---: | ---: |
| aishell3 | 6,177 | 748 | 3,495,088 |
| csemotions | 3,691 | 1,259 | 6,434,400 |
| emilia | 8,192 | 2,228 | 16,819,568 |

191 项单元测试、Ruff、diff check 和 34 个数据契约检查通过。生产验收冻结本次
实际误差、重复一致性、八卡对照和 1.332× 吞吐证据；不复用旧 BF16 零差异验收。
验收脚本以 token 差异 <0.1%、重复零差异及满载耗时 ≤1.5× 作为本次启动检查；
这是本次经验验收界限，不是对未测输入的数学误差保证或逐长度运行策略。
