# 04 · 音频时间轴与裁剪来源

## 裁剪归 selection

基础一行代表一个独立编码音频样本；短句、长录音、对话都可以作为来源。
是否需要裁剪及必要的裁剪处理，统一由 [12 selection](12-selections.md#音频区间决策与新数据集接入)负责。
需要裁剪时，selection 产出实际片段音频及其对应文本，作为后续完整消费的样本。
不设置独立片段引用表，也不把“父音频 + 待应用区间”交给 codec、speaker 各自裁剪。
上游已经提供独立剪辑文件时直接使用该样本；原录音中的时间范围不能再次应用于片段 bytes。

原始样本及已发布快照保持不变。裁剪产物需要新的样本身份，并记录父样本、父音频摘要、
原生起止帧、解码/裁剪方法及文本来源；产物的音频摘要、帧数和时长描述实际片段。
片段局部时间轴从零开始，父录音中的坐标仅用于追溯，不能再次用于裁剪片段。
一条父音频的多个片段各有独立身份；片段文本必须对应实际音频，不能直接沿用整段转写。

当前 selection 执行器只支持完整样本筛选，尚未实现裁剪产物发布。
本章定义职责与验收要求，不新增未经实现的目录、schema 或裁剪身份算法。
启用裁剪前须实现并验证 selection 的样本产出、来源关联及三个特征任务的输入衔接。

## 时间轴

frame 指每声道采样帧，区间为 `[start_frame,end_frame)`；0 ≤ start < end ≤ 实际解码有效帧数。
裁剪必须固定 decoder 与版本、原生采样率/声道、延迟、有效区间及秒到帧的舍入策略。
来源秒数保留用于追溯，实际裁剪使用整数帧；重采样前后坐标不得混用。
基础 num_frames 是读取器报告的头信息，不自动证明有效解码长度；不能为匹配头信息补零或截断。
AAC/M4A 等需要专门核验 edit list、编码延迟与尾部 padding。

selection 完成原生时间轴裁剪后，codec、speaker 按各自 profile 对完整产物做声道处理及重采样。
先编码长音频再按比例截 token 与先裁剪音频再编码不等价，不能相互替代。
非连续拼接、去除内部停顿、静音修剪或音量归一化不是默认裁剪操作，启用时需单独定义并验证。

## Speaker、混语与关系

单段确定单 speaker 才填单 speaker_id；多人可为空，轮次/区间信息保存在分段标注中。
本地 S1/S2 限定录音/会话；游戏角色限定语言与来源；跨数据集同人须经过单独映射。
顶层 language 为空不代表无用，可通过分段语言标注支持 selection 的片段选择；方言原值保留。
recording/group 关系用于追溯及下游隔离，group_id 相同不证明同 speaker。
重叠片段、多麦克风、不同编码的重复关系须明确，不能直接相加声称独立语音时长。
